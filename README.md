## 事实如何保持新鲜

本仓库不把“链接还能打开”冒充成“内容仍然正确”，而是分三层维护：

1. **正文逐条引用**：关键数字和产品定义优先引用平台官方、券商官方、监管或税务机关的一手页面。
2. **结构化来源库**：`data/sources.json` 记录来源 ID、支持的主张、最后人工核验日和复核周期。
3. **每周自动巡检**：GitHub Actions 检查来源可达性、复核期限、内部链接和四个邀请码；发现异常自动创建 Issue。语义变化仍由人工复核并写入 `CHANGELOG.md`。

任何人都可以提交 Issue 或 PR。纠错时请提供：原文位置、你认为已变化的事实、官方来源、页面日期/截图日期以及建议改法。

## 这份教程坚持什么

- **先分清产品，再谈怎么下单。** “跟踪 AAPL”不自动等于“持有 Apple 股票”。
- **先看一手来源，再看营销文案。** 平台公告、帮助中心、合同条款优先于二手文章。
- **时间敏感信息必须带日期。** 数量、费率、杠杆、开放地区和入口都可能变化。
- **不替用户虚构信息。** 如果某功能未对账户开放，就比较其他真实可用路线。
- **推广透明。** CPS 入口醒目展示，返佣关系同样醒目披露。
